# V42.4 UI integration

Ports the teammate's V42.4 folder selectively into the current main baseline.

- Use the supplied cropped PioVation logo in the public header, workspace header, mobile drawer and sidebar.
- Replace the public landing layout with the supplied DE/EN messaging, benefits, applications, workforce and architecture sections. Retain working sign-in, registration, the bilingual end-user section and formatted guide links.
- Add the read-only Local Computer source to Files & DMS. User selection is required; no file upload, cloud sync, background indexing or AI access is introduced. The new explorer currently uses German labels.
- Expose Worker Factory as its own Digital Workers tab and route Create worker there. Retain the existing worker registry and version data.
- Retain App.tsx authentication, OIDC callback/refresh/logout, Documentation routes/catalog, guide generation, dependency lockfile, deployment files and CI configuration.
- Use port 3000 for local development. No running processes are stopped or restarted by this integration.

The supplied V42.1 standalone landing/auth behavior was not imported: it would have removed the current OIDC integration. Archived duplicate specs and migrations were also excluded. Package dependencies and version remain unchanged.

## Review

Run `npm run dev` in `app/webui`, then visit `http://localhost:3000/`.

- Switch DE/EN, check the revised landing sections and both public guide links.
- Check Sign in, Sign up, callback behavior and sign-out against the configured identity provider.
- Enter the demo, check Documentation, then Digital Workers > Worker Factory and DW Settings.
- In Files & DMS, choose Local Computer, select a test folder, navigate subfolders and preview/download files. Verify switching back preserves existing DMS content.
- Check desktop/mobile layouts and keyboard navigation.

Automated checks cover model/document behavior, rendered DE/EN landing and guides, route preservation and the fallback folder tree. Native picker permissions, real identity-provider sign-in and browser visual review still require manual verification.
